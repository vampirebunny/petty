# Boop Boop

A small virtual pet. Needs change with real time, including while the app is closed. Play does not require an account screen. Before adoption, the app checks a store age signal when one exists, then asks whether the person is at least 13 and records acceptance of the terms and privacy policy. A Yes for someone 13 or older can create an anonymous Supabase user and sync a compliance record when the network is available. A No, or a store signal under 13, stays on the device and is not sent anywhere.

## Run

```sh
npm install
npm test
npx expo start
```

Open the project in Expo Go on a phone signed into the same Expo account as this machine. The dev server prints a QR code. Expo Go has no store age API, so the consent screen asks the age question. A development build is required before Apple Declared Age Range or Play Age Signals can answer.

### Environment variables

Consent sync needs two public Supabase values (Project Settings → API in the dashboard). Use the project URL and the **anon** / **publishable** key — never the `service_role` key.

**Local development** — create `.env.local` in the repo root (gitignored, not committed):

```sh
EXPO_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=your_anon_or_publishable_key
```

Restart `npx expo start` after creating or changing the file. Without these, the app still runs; consent sync is skipped.

**EAS cloud builds** — `.env.local` is not uploaded. The same two vars live on the Expo project for `development`, `preview`, and `production`. Check or update them after `eas login`:

```sh
npx eas-cli@latest whoami
npx eas-cli@latest env:list production
npx eas-cli@latest env:set --name EXPO_PUBLIC_SUPABASE_URL --value "https://YOUR_PROJECT_REF.supabase.co" --environment production --environment preview --environment development --visibility plaintext --type string --non-interactive
npx eas-cli@latest env:set --name EXPO_PUBLIC_SUPABASE_ANON_KEY --value "your_anon_or_publishable_key" --environment production --environment preview --environment development --visibility plaintext --type string --non-interactive
```

Migration SQL in `supabase/migrations/` is applied only by the project owner, with `supabase db push` after the CLI is linked. Do not apply it from an agent or another script.

### Build (iOS and Android)

EAS is already configured (`eas.json`, project linked under `@vampirebunny/boop-boop`). Log in, then build:

```sh
npx eas-cli@latest login
npx eas-cli@latest build --platform all --profile production
```

Profiles:

| Profile | Use |
| --- | --- |
| `production` | Store-ready binaries (App Store / Play). Needs Apple Developer Program for iOS; Play Console for Play Store. |
| `preview` | Internal installable builds for devices. |
| `development` | Dev client (needs `expo-dev-client`). Required to exercise store age APIs. |

Platform-only examples:

```sh
npx eas-cli@latest build --platform ios --profile production
npx eas-cli@latest build --platform android --profile production
npx eas-cli@latest build --platform android --profile preview
```

First iOS device/store build prompts for Apple credentials; EAS can manage signing. Android keystore can be generated by EAS on first build.

On the home screen the name and actor stay sticky. Tinted need rings (Tummy, Energy, Mood) sit below the animation. Each has a caption for its level and turns red when low; Tummy is the inverse of the stored hunger, so a full ring is always good. Action buttons are chunky candy-colored tiles, one tint per action. The stage is taller than wide (640×680) with a deep floor so the pet can wander; the adoption preview still uses the top half. Actions are sit, give paw, speak, sleep/wake, eat, drink, and throw ball. Idle is not a button: the pet idles on its own when nothing else is running. While resting (standing, panting, or purring) it occasionally barks or meows unprompted, at most about once a minute. Any action other than sleep wakes a sleeper. Tap the stage to soft-drop the ball from high up, or flick to throw; stroke to pet. `{name}'s personality` expands archetype and attribute scores. Settings (formerly Debug) jumps 1, 6, or 24 hours and can reset the pet. Its "New pet" button deletes the current pet and starts adoption again, with no confirmation and no way back.

## Layout

- `src/age` stores the age record and terms acceptance, merges store signals, and decides who can play or purchase.
- `src/compliance` signs in an anonymous Supabase user after a 13+ confirmation and syncs consent records. `upgradeAnonymousAccount` is a stub.
- `src/config/legal.ts` holds the live Terms and Privacy URLs and their versions.
- `modules/age-signals` is the local native module for Apple Declared Age Range and Play Age Signals. `ios/` and `android/` are generated and are not edited by hand.
- `src/sim` is the pure simulation. It does not import React, read the clock, or generate random numbers itself. Time arrives as elapsed milliseconds. `config.ts` holds the tunable numbers.
- `src/storage` is the `PetStorage` interface and the AsyncStorage implementation. A later backend would be a second implementation.
- `src/state/usePet.ts` loads the pet, advances time on launch, foreground, and every few seconds, applies feed, rest, and pet, and saves.
- `src/ui` draws the bars, buttons, settings panel, and actor. `PetView` draws the scene and pet from state and animation cues.
- `src/screens/HomeScreen.tsx` is the active pet screen.
